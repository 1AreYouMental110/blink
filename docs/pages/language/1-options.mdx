# Options
Options go at the top of a source file, and allow you to configure the output of Blink.
```blink copy
option [OPTION] = [VALUE]
```

## `Casing`
Default: `Pascal`  
Options: `Pascal`, `Camel`, `Snake`  

Controls the casing with which event/function methods generate.
```blink copy
option Casing = Camel
```

## `ServerOutput`, `ClientOutput`, `TypesOutput`
These options allow you to specify where Blink will generate the respective output files.
```blink copy
option TypesOutput = "../Network/Types.luau"
option ServerOutput = "../Network/Server.luau"
option ClientOutput = "../Network/Client.luau"
```

## `Typescript`
Default: `false`  

Tells Blink whether to generate TypeScript definition files alongside Luau files.  
The generated `d.ts` files are placed in the same path as your output files.
```blink copy
option Typescript = true
```

## `UsePolling`
Default: `false`

Instructs the compiler to automatically output all events with a polling API.
```blink copy
option UsePolling = true
```

## `FutureLibrary` and `PromiseLibrary`
In order to use future and promise yield types with functions a path to each library used must be specified  
```blink copy
option FutureLibrary = "ReplicatedStorage.Packages.Future"
option PromiseLibrary = "ReplicatedStorage.Packages.Promise"
```

## `SyncValidation`
Default: `true`

Controls if Blink will check whether a sync call yielded.

## `WriteValidations`
Default: `false`

Controls if Blink will check types when writing them (firing an event/invoking a function). Helpful for debugging and during development, but it might result in degraded performance. It is encouraged you disable this option in production.
<Callout>
    Blink validates builtin primitives and container shape for arrays, maps, sets, and structs. Deep element validation follows the schema as values are serialized.
</Callout>

## `ManualReplication`
Default: `false`

Controls if Blink will replicate events and functions automatically at the end of every frame.  
When set to `true` automatic replication will be disabled and a `StepReplication` function will be exposed instead.

## `RemoteScope`
Default: `""`

Adds a prefix to the events generated by this Blink instance. For example a value of `"PACKAGE"` creates events `"PACKAGE_BLINK_RELIABLE_REMOTE"` and `"PACKAGE_BLINK_UNRELIABLE_REMOTE"`.
If the option is not specified, they will just be `"BLINK_RELIABLE_REMOTE"` and `"BLINK_UNRELIABLE_REMOTE"`.<br/>
This is particularly useful if you're using Blink inside of a package, and don't want to interfere with a game's own Blink setup.

## Runtime Guard Options
These options configure generated packet guardrails.
```blink copy
option MaxPacketBytes = 1048576
option MaxReliablePacketBytes = 1048576
option MaxUnreliablePacketBytes = 1000
option RateLimitPerSecond = 0
option RateLimitBurst = 0
option MaxQueuedEvents = 256
option MaxPendingInvokes = 256
option InvokeTimeoutSeconds = 0
option SecurityProfile = Development
```

`SecurityProfile` can be `Development`, `Production`, or `Competitive`. The profile supplies defaults for packet limits, rate limits, queue limits, pending invoke limits, and invoke timeouts. Explicit options override profile defaults.

`MaxPacketBytes` is the fallback packet size limit. `MaxReliablePacketBytes` and `MaxUnreliablePacketBytes` override it per transport. Rate limiting is disabled when `RateLimitPerSecond` is `0`. `InvokeTimeoutSeconds` is disabled when set to `0`.

Events and functions can override the packet, queue, and rate settings:
```blink copy
event Attack {
    From: Client,
    Type: Reliable,
    Call: SingleAsync,
    RateLimitPerSecond: 20,
    RateLimitBurst: 40,
    MaxQueuedEvents: 64,
    Data: u16
}
```

## Runtime Feature Options
```blink copy
option ExposeMetrics = true
option EnableMiddleware = true
option EnablePrediction = true
option EnableStateChannels = true
option UseEmptyInstanceOptimization = true
option ProtocolVersion = 2
option UseVarints = true
option UseBitPacking = true
option UseStringDictionaries = false
option UseBufferPooling = true
option BufferPoolLimit = 64
```

Generated client and server modules expose:
- `Stats()` for copied counters.
- `Configure(options)` for runtime guard changes.
- `Use(hookName, callback)` for middleware hooks.
- `CancelInvocations(reason?)` for cancelling pending client invokes.
- `SetGroup`, `AddToGroup`, `RemoveFromGroup`, and `GetGroupPlayers` for named audiences.
- `Prediction.Begin`, `Prediction.Ack`, and `Prediction.Rollback`.
- `State.DefineChannel` for local dirty-state channels.

Server-origin events also expose `FireGroup(groupName, ...)`. Client-origin events expose `Predict(...)`, which sends the event and returns a local prediction id.

`ProtocolVersion = 2` enables length-prefixed event frames, per-event recovery inside a packed reliable packet, prediction sequence ids and acks, optional integer varints, bit-packed booleans/optional presence, optional string dictionaries, and buffer pooling. Set individual `Use...` flags to disable a v2 wire optimization during rollout.

State channels can also be declared in schema:
```blink copy
channel PlayerState {
    Scope: Player,
    TickRate: 20,
    Delta: true,
    Data: struct {
        Health: u8,
        Stamina: u8,
        Equipped: string(0..32)?
    }
}
```

Generated server modules expose `Set`, `SetPlayer`, `SetAll`, `SetList`, `SetGroup`, and struct-backed `Patch` variants. Generated client modules expose `On`, `Get`, and `Version`.
